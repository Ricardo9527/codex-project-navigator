# 可选 macOS 启动动画

默认安装继续使用普通启动器。只有在本地放入 `assets/launcher/animation.json` 与 `frames/frame-000.png` 等连续透明帧后，构建命令才使用 Swift 动画启动器；其 Node 路径来自 `data/install.json`。动画与启动任务并行，二者完成后退出。

右侧 Codex 唤醒动画另需 `assets/codex/animation.json`、`frames/`、`idle.png` 和 `source/official.png`。清单包含 `fps`、`frameCount`、`impactOffsetMs`、`readyDelayMs`。素材由使用者准备，仓库不包含个人视频或图标成片。运行 `npm run build:launcher` 构建辅助程序，再正常重载资料库后台服务。

图标操作由资料库后台服务执行。启动器通过本地请求队列提交固定的播放任务并取得结果，不直接修改其他应用的自定义图标。这样保持了后台待机图标和启动动画的执行身份一致；是否有应用管理权限仍由 macOS 决定，不修改系统权限。辅助程序输出具体失败阶段，动画失败与 Codex 启动失败分别提示。

Codex 主窗口可连接且达到左侧接触时点后播放。结束使用官方彩色图标，Codex 进程退出后使用待机态。系统图标接口可能跳帧，动画显示、节奏和冷启动效果需要本机实测。公开版普通启动路径不启用此功能。

验证：队列完成回传、错误保留、过期请求不执行均有测试。该功能只适用于 macOS。
