# Codex 更新兼容检查

检查或适配更新时优先核对以下六项；先确认实际启用状态，不凭旧记录假定当前配置。比较版本号和构建号，同一版本号也可能重新发布不同构建。

1. **网络代理**：系统代理、选择性 TUN 与 DNS 守护；核对新增连接目标及路由。诊断期间不擅自更换节点、切换 TUN 或重启 Clash。
2. **图片 file ID 桥接**：实际服务地址、启用的桥接版本、上传与 ID 复用、失效重传，以及 HTTP/SSE/WebSocket 接续。后台服务在运行不等于真实传输通过；旧桥接仍运行时单独列明。
3. **项目导航**：项目旁入口、卡片读取、搜索/预览、消息与轮次来源定位；核对模块文件名、导出用途和参数契约，验证两种项目 ID 与根目录、草稿背景及关闭导航后的聊天恢复。
4. **项目记录维护**：Skill 与 MCP/CLI 接入、更新按钮、任务状态收尾、成果/聊天覆盖、独立周检。保留用户暂停状态；核对线程复用是否已实现，不将计划写成已交付。
5. **长上下文配置**：项目配置是否仍生效、模型实际支持的窗口与压缩阈值，以及整理专用线程配置；区分项目级与单线程级设置。
6. **启动器与 Dock 图标**：启动参数、127.0.0.1 调试端口、导航监管服务、图标状态与动画；确认退出后的状态恢复。已停用的重签名副本实验不算当前运行依赖。

先对更新包做只读兼容核对，再按具体差异实施最小修复。相关检查通过后不重复全量审阅；配置、静态契约、真实窗口及真实发送分别报告，未执行的项目标为待验收。普通验证不强行退出或重启 Codex；服务需要重新接入时仅操作 local.codex.project-library。
